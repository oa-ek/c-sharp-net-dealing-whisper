## 1. Назва проєкту
Захищений месенджер з наскрізним шифруванням **«Whisper»**.

## 2. Мета розробки
Створення захищеної системи для обміну повідомленнями з фокусом на приватність. Система має забезпечити наскрізне шифрування (E2EE) за протоколом **X3DH** та архітектуру, що унеможливлює доступ сервера до вмісту переписки.

## 3. Функціональні вимоги
Система реалізує наступні функції згідно з архітектурою сучасних захищених месенджерів:

### 3.1. Для користувача:
* **Автентифікація:** реєстрація за допомогою Email та пароля, автоматична генерація ключів на стороні клієнта.
* **Мультидевайсність:** прив'язка декількох пристроїв (ноутбук, смартфон) до одного облікового запису.
* **Керування ключами:** автоматична генерація та публікація One-Time PreKeys на сервер для забезпечення асинхронного шифрування.
* **Чат:** створення діалогів, відправка та отримання текстових повідомлень у реальному часі.

### 3.2. Для серверної частини:
* **Керування сесіями:** валідація JWT-токенів та контроль активних DeviceId.
* **Сховище публічних ключів:** зберігання та видача "бандлів" ключів (Identity, Signed, One-Time) для ініціалізації чату.
* **Маршрутизація:** доставка зашифрованих пакетів даних між пристроями через SignalR.

## 4. Нефункціональні вимоги
* **Безпека:** наскрізне шифрування (E2EE), хешування паролів за допомогою **BCrypt**, використання HTTPS та WSS.
* **Надійність:** використання **IndexedDB (через Dexie.js)** на клієнті для гарантованого збереження даних при збоях.
* **Продуктивність:** час доставки повідомлення має бути швидким.
* **Масштабованість:** можливість додавання нових типів медіа-даних без зміни протоколу шифрування.

## 5. Опис бази даних
Проєкт використовує гібридну модель збереження даних:

### 5.1. PostgreSQL (Користувачі та безпека)
* **Users:** профілі, хеші паролів, 2FA, `PfpLink`.
* **UserDevices:** публічні ключі пристроїв (`Identity`, `SignedPreKey`), токени.
* **OneTimePreKeys:** одноразові публічні ключі.
* **Chats & Members:** структура чатів.
* **UserPrivacySettings:** налаштування видимості та безпеки.

### 5.2. MongoDB (Повідомлення та вкладення)
* **Messages:** `Ciphertext` (зашифрований текст), метадані, статуси.
* **Attachments:** дані про файли (назва, розмір, `FileLink` на MinIO).
* **Reactions:** емодзі-реакції користувачів.

### 5.3. IndexedDB + Dexie.js (Клієнтське сховище)
* **Messages:** локальна розшифрована історія.
* **KeyStore:** приватні ключі (ніколи не передаються на сервер).

## 6. Інтерфейс користувача
Інтерфейс розробляється на базі React з використанням Tailwind CSS:
* **Вікно авторизації:** вхід та ініціалізація криптографічних ключів.
* **Головний екран (Sidebar):** список активних чатів з останніми повідомленнями.
* **Область повідомлень:** динамічна стрічка повідомлень.
* **Керування профілем:** налаштування безпеки та перегляд списку підключених пристроїв.

## 7. Технічні вимоги
* **Backend:** C# (.NET 10.0), Entity Framework Core, SignalR.
* **Frontend:** React (TypeScript), Dexie.js (IndexedDB wrapper).
* **Криптографія:** протокол X3DH (Extended Triple Diffie-Hellman), Key-Wrapping.
* **Архітектура:** багатошарова (N-Layer: Domain, Application, Persistence, WebAPI).

## 8. Вимоги до середовища

Система розробляється як кросплатформове веб-рішення, що мінімізує вимоги до кінцевого обладнання користувача.

* **Операційна система:** будь-яка сучасна ОС (Windows 10/11, macOS, Linux, Android, iOS), що підтримує роботу веб-браузера.
* **Програмне забезпечення (клієнт):** будь-який сучасний браузер на базі двигуна Chromium (Google Chrome, Microsoft Edge, Brave), Safari або Mozilla Firefox.
    * Підтримка **IndexedDB** для роботи локальної бази даних (Dexie.js).
* **Серверні вимоги (для розгортання):** середовище виконання .NET 10 Runtime.
    * Docker / Docker Compose.
    * Вільне місце на диску: не менше 500 МБ для ядра системи (без врахування сховища медіафайлів).
